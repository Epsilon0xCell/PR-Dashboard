PR-Dashboard: the order rail

Every pull request is a ticket on the rail. This repository keeps the count current, clips the open ones up where they can be seen, and stamps the finished ones off the line.

What is on the rail

PR-Dashboard tracks the pull requests of the Epsilon0xCell account. A scheduled workflow keeps a running counter in status.md and in main.py itself, and dashboard.html reads the live state of the account's pull requests straight from the GitHub API.

COUNTED

The pieces

main.py

The counter. A GitHub Actions workflow advances its number each time a pull request is merged, so the file itself carries the running total of merged work.

status.md

The same count, kept in step by the scheduled workflow: one line that always answers how many pull requests have been merged.

dashboard.html

A self contained page that fetches this account's pull requests from the GitHub API and lays them out in a table: number, title, repository, state, and dates.

pull-request-check.py

An interactive checker: give it a repository and it walks the pull requests, printing each one's number, title, author, state, comment count, and changed file count, and can export the walk to CSV.

How the rail stays current

  • Two workflows live under .github/workflows: update.yaml runs on a schedule and on merged pull requests to advance the counter, and merge.yml supports the merge side of the line.
  • The counter lives in the code and in status.md together, so the number is readable without running anything.
  • PR.png in the repository is the product screenshot of the dashboard itself.

Reading the tickets

Open pull requests are the tickets still clipped to the rail; merged ones are stamped and taken down. The dashboard page shows both kinds as the API reports them, so what you see is the account's real queue, not a snapshot.
